# Лабораторная работа №4 — LazySequence и Streams

Лаба про то, как работать с последовательностями, которые **нельзя удержать в памяти целиком**:
бесконечными (заданными правилом, как Фибоначчи) и просто очень большими (файлы).
Реализованы АТД `LazySequence<T>`, семейство потоков `Stream<T>` и две тематические задачи
поверх них: онлайн-статистика (вариант 4) и сортировка потока бинарной кучей (вариант 10.2).
Алгебра ординалов (вариант 2) получилась сама собой — без неё бесконечные списки не индексируются.

## Из чего состоит

```
core/
  DynamicArray.h, LinkedList.h     — база из прошлых лаб
  Sequences/                       — Sequence и его реализации (тоже из прошлых лаб)
  Lazy/
    Ordinal.h                      — числа вида ω·k + n (длины и индексы бесконечных списков)
    Generator.h                    — базовый генератор + листовые (готовый список, рекуррентное правило)
    LazySequenceGenerators.h       — генераторы-операции: Concat, Insert, Map, Where, Subsequence
    LazySequence.h                 — сам ленивый список (тонкая обёртка над генератором)
  Streams/
    ParentsStream.h                — интерфейсы ReadOnlyStream / WriteOnlyStream
    ReadStreams.h                  — чтение: из Sequence, из LazySequence, из строки, из файла
    WriteStreams.h                 — запись: в Sequence, в файл
atd/
  BinaryHeap.h                     — бинарная куча (min/max через компаратор)
  FixedQueue.h                     — очередь фиксированной длины (скользящее окно)
  Stack, Queue, Deque              — из лабы 3
tasks/
  OnlineStats.h                    — медиана/мин/макс/среднее потока в режиме онлайн
  StreamSorter.h                   — сортировка потока кучей: in-memory и внешняя
  Hanoi.h                          — Ханойская башня (прикладная задача из лабы 3)
ui/                                — консольное меню (песочница, калькулятор ординалов, задачи, авто-демо)
tests/                             — модульные тесты (156 штук)
data/                              — файлы для потоков (есть пример sample_numbers.txt)
```

## Как слои связаны

Зависимости идут строго снизу вверх: каждый слой строится на тех, что ниже,
и ничего не знает о тех, что выше (поэтому, например, `Ordinal` лежит в core,
а не в atd — он нужен ленивым спискам, а core не может зависеть от atd).

```
  ui, tests        пользуются всем, своих структур данных не определяют
      ▲
   tasks           тематические задачи:
      │              OnlineStats  = две BinaryHeap + ReadOnlyStream
      │              StreamSorter = BinaryHeap + Read/WriteStream + файлы
      ▲
    atd            контейнеры, собранные из деталей core:
      │              BinaryHeap ← DynamicArray
      │              FixedQueue ← Queue ← MutableListSequence
      │              Stack, Queue, Deque ← Sequences
      ▲
    core           фундамент (внутри тоже слоями):
                     DynamicArray, LinkedList        — сырое хранение
                     Sequences   ← на массиве/списке
                     Lazy        ← Ordinal + генераторы + LazySequence (на Sequences)
                     Streams     ← потоки; читать умеют в т.ч. из Lazy
```

Плюс общий `my_except.h` с исключениями — его включают все слои. Поэтому он лежит
в корне проекта, а UI ловит любую ошибку (кучи, ординала, потока, файла) одним
`catch (const ParentForErrors&)` — у всех исключений один родитель.

## Как это устроено (коротко)

**Ordinal.** Обычным `int` длину бесконечного списка не записать, поэтому есть свой тип числа:
`ω·k + n`, где ω — «бесконечность». Сложение **некоммутативно**: `2 + ω = ω`
(конечный кусок тонет в бесконечности), но `ω + 2 = ω+2` (два элемента *после* бесконечного блока).
Это не причуда, а точное описание склейки списков: длина `[a,b] ++ бесконечный` — это ω,
а `бесконечный ++ [a,b]` — это ω+2.

**Generator.** Иерархия с виртуальным `Get(Ordinal)`: каждый вид списка — свой класс.
`SequenceGenerator` отдаёт готовые элементы, `RecurrenceGenerator` считает по правилу
(и запоминает посчитанное — мемоизация), `ConcatGenerator` склеивает два генератора,
`MapGenerator`/`WhereGenerator` лениво преобразуют и фильтруют, `InsertGenerator` — отложенная вставка.
Операция над списком ничего не вычисляет — она просто оборачивает генератор в новый.

**LazySequence.** Тонкая обёртка: держит указатель на генератор и делегирует ему всё.
Элементы материализуются только когда их попросят (`Get`), и второй раз не считаются.
Снаружи это видно через `GetMaterializedCount()`. Самое приятное — `GetByOrdinal`:
у склейки двух бесконечных списков можно спросить элемент `ω+3` и получить ответ мгновенно,
не перечисляя первый список «до конца» (которого нет).

**Streams.** Поток — это другая модель доступа: не «дай i-й», а «дай следующий» (`Read`),
чтение съедает элемент. Никакой алгебры (Concat/Map нет) — только курсор и данные.
Источники: последовательность, ленивый список (может быть бесконечным!), строка, файл.
У потока можно спросить `IsFinite()` — и, например, сортировка честно откажется
от бесконечного входа, вместо того чтобы зависнуть.

**OnlineStats (вариант 4).** Медиана бесконечного потока за один проход — на двух кучах:
max-куча держит меньшую половину чисел, min-куча — большую, медиана всегда на их вершинах.
O(log n) на элемент, и не нужно ни хранить весь поток, ни ждать его конца.

**StreamSorter (вариант 10.2).** Сортировка — противоположный случай: пока не увидишь все
элементы, не выдашь даже первый. Два режима: in-memory (всё в кучу, извлекаем по порядку)
и внешняя — для файлов, которые не влезают в память: режем на куски, каждый сортируем и
сбрасываем во временный файл, потом k-путевое слияние через ту же кучу
(в памяти одновременно только один кусок и по одной «голове» от каждого файла).

## Как собрать и запустить

Проект собирается CMake'ом, три таргета:

- **`lab4_tests`** — все тесты (собраны с AddressSanitizer/UBSan, так что заодно ловят ошибки памяти).
  Запустить — и смотреть на `[OK]`: их 156, провалов быть не должно.
- **`lab4_ui`** — консольное меню:
  1. *Песочница LazySequence* — создаёшь список (вручную или по правилу: натуральные,
     прогрессия, Фибоначчи, факториалы), применяешь операции и смотришь, как меняются
     первые элементы, длина-ординал и счётчик материализации. Есть прыжок через ω
     и склейка списков разных типов (int ++ double — через ленивый Map).
  2. *Калькулятор ординалов* — сложение/сравнение, с подсказкой по записи (k n).
  3. *Онлайн-статистика* — ручной режим (вводишь числа, медиана после каждого) и
     авто-режимы: случайные данные с настройкой параметров, первые N бесконечного потока, файл.
  4. *Сортировка потока* — источник (ручной/рандом/файл), направление, режим
     (in-memory / внешняя с настройкой chunkSize), замер времени, сохранение в файл.
  5. *Авто-демо* — прогон всех заготовленных сценариев одной кнопкой.
- **`lab4`** — пустая заготовка под main.

Файлы для потоков лежат в `data/` (формат: одно целое число в строке).
При запуске UI из CLion рабочая папка — `cmake-build-debug`, поэтому путь к примеру
`../data/sample_numbers.txt`; из терминала в корне проекта — просто `data/sample_numbers.txt`.

## Тесты

Покрыто всё по слоям: `Ordinal` (включая некоммутативность и переполнение), каждый генератор
отдельно, `LazySequence` (ленивость проверяется через `GetMaterializedCount`, прыжки через ω,
цепочки Map→Where, тройные склейки ω·3), потоки (включая roundtrip через файл и миллион
элементов), медиана (после каждого элемента, бесконечный источник), сортировка
(оба режима на одних данных дают одинаковый результат, 200к элементов под санитайзером).
Граничные случаи и некорректные данные — пустые списки/потоки, выход за границы,
бесконечный вход там, где нужен конечный, битые файлы.
